# РуПруф

Проверка русского текста прямо в браузере на своём компьютере: [LanguageTool](https://github.com/languagetool-org/languagetool) с исправленным
словарём и фильтром ложных срабатываний. Всё работает локально.

Что здесь лучше, чем в обычном LanguageTool:

- **«ё» обязательна**: «еще» и «темно-синий» — ошибки, словарь на основе [словаря Лебедева](http://scon155.phys.msu.su/~swan/orthography.html);
- **меньше ложных ошибок**: составные слова (`фьюжн-ресторан`), «что бы … ни», исправленные правила грамматики;
- **свои слова** со всеми формами (склонениями): добавили вы, допустим, «Брумзик» — принимаются и «Брумзика», и «Брумзиком»;
- **режим для художественного текста** (`prose`): речь персонажей, имена, заикания (`П-прямо`), растяжки (`Не-е-ет`);
- **кавычки**: непарные `«»` и `«»` внутри `«»` (нужны `„“`).

## Что понадобится

- Windows 10/11, Linux или macOS (Intel или Apple Silicon).
- **Память: 8 ГБ на компьютере, лучше 16.** Самой проверке хватает ~3 ГБ, 1–1,5 ГБ уходит на Java, остальное
  система использует как кэш, и с ним проверка идёт быстрее.
- **Место на диске: ~3 ГБ**, с n-граммами (см. ниже) ещё ~5 ГБ.
- Браузер с расширением LanguageTool: [Chrome, Edge, Яндекс](https://chromewebstore.google.com/detail/oldceeleldhonbafppcapldpdifcinji),
  [Firefox](https://addons.mozilla.org/firefox/addon/languagetool/).
- **Podman или Docker**: программа для контейнеров, в которых работают LanguageTool и всё остальное. Больше ничего
  ставить не нужно, ни Java, ни Python.
- **Git**: чтобы скачать проект и потом получать обновления одной командой.

## Установка

Выберите свою систему. Все команды вводятся в терминале: на Windows это PowerShell (Пуск → «PowerShell»),
на macOS — «Терминал» (Программы → Утилиты), на Linux — любой терминал.

### Windows

1. **Git.** Скачайте установщик с <https://git-scm.com/download/win> и установите с настройками по умолчанию.
2. **Podman** (или Docker Desktop, см. ниже). Скачайте Podman Desktop с <https://podman-desktop.io> и установите.
   При первом запуске он предложит установить Podman и создать «машину» (Podman machine): соглашайтесь, а если
   попросит включить WSL, перезагрузите компьютер. Затем в Podman Desktop откройте Settings → Resources и включите
   **Compose** (кнопка Setup / Install).
   *Docker вместо Podman:* установите [Docker Desktop](https://www.docker.com/products/docker-desktop/), запустите
   его и дождитесь зелёного «Engine running». Compose в нём уже есть.
3. **Проверьте**: откройте новое окно PowerShell и выполните `podman compose version` (или `docker compose version`).
   Должна появиться версия, а не ошибка.
4. **Скачайте проект** в папку, например, `C:\ruproof`:

   ```powershell
   git clone https://github.com/Razhon/RuProof C:\ruproof
   cd C:\ruproof
   ```

5. **Разрешите запуск скриптов** (один раз; Windows по умолчанию запрещает скрипты PowerShell):

   ```powershell
   Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
   ```

   На вопрос ответьте `Y`. Если Windows всё равно пишет, что скрипт не подписан, выполните `Unblock-File build\rpdict.ps1, update.ps1`.
6. **Запустите** первую сборку:

   ```powershell
   .\build\rpdict.ps1
   ```

   Первый раз это занимает 5–15 минут: скачиваются образы (~1 ГБ) и собирается словарь. Если после перезагрузки
   компьютера проверка не работает, запустите Podman Desktop или Docker Desktop и выполните `.\build\rpdict.ps1` ещё раз
   (без первой сборки это ~20 секунд).

### Linux

1. **Git и Podman** (или Docker) из пакетов системы:
   - Debian, Ubuntu, Mint: `sudo apt install git podman podman-compose`
   - Fedora: `sudo dnf install git podman podman-compose`
   - Arch: `sudo pacman -S git podman podman-compose`

   *Docker вместо Podman:* поставьте Docker Engine по [инструкции для вашей системы](https://docs.docker.com/engine/install/)
   и добавьте себя в группу `docker`: `sudo usermod -aG docker $USER`, затем выйдите из системы и войдите снова.
2. **Проверьте**: `podman compose version` (или `docker compose version`). Должна появиться версия, а не ошибка.
3. **Скачайте проект**:

   ```sh
   git clone https://github.com/Razhon/RuProof ~/ruproof
   cd ~/ruproof
   ```

4. **Запустите** первую сборку:

   ```sh
   build/rpdict.sh
   ```

   Первый раз это занимает 5–15 минут: скачиваются образы (~1 ГБ) и собирается словарь.
5. **Автозапуск после перезагрузки.** С Docker серверы поднимаются сами. С Podman (rootless) включите
   `systemctl --user enable --now podman-restart.service` и `loginctl enable-linger $USER`; если такого
   сервиса нет, после перезагрузки запускайте `podman compose up -d` в папке проекта.

### macOS

1. **Git.** Выполните `git --version`. Если Git не установлен, macOS сама предложит поставить инструменты
   разработчика: соглашайтесь.
2. **Podman** (или Docker Desktop, см. ниже). Скачайте Podman Desktop с <https://podman-desktop.io>, перетащите в
   «Программы» и запустите. Он предложит установить Podman и создать машину (Podman machine): соглашайтесь и при создании
   **поставьте память (Memory) не меньше 6 ГБ**: по умолчанию там 2 ГБ, и LanguageTool с ними не запустится.
   Уже созданную машину можно поменять командой `podman machine stop; podman machine set --memory 6144; podman machine start`.
   Затем в Settings → Resources включите **Compose**.
   *Docker вместо Podman:* установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) для своего
   процессора (Apple или Intel), запустите и в Settings → Resources поставьте Memory не меньше 6 ГБ.
3. **Проверьте**: `podman compose version` (или `docker compose version`). Должна появиться версия, а не ошибка.
4. **Скачайте проект**:

   ```sh
   git clone https://github.com/Razhon/RuProof ~/ruproof
   cd ~/ruproof
   ```

5. **Запустите** первую сборку:

   ```sh
   build/rpdict.sh
   ```

   Первый раз это занимает 5–15 минут: скачиваются образы (~1 ГБ) и собирается словарь. Если после перезагрузки
   компьютера проверка не работает, запустите Podman Desktop или Docker Desktop и выполните `build/rpdict.sh` ещё раз
   (без первой сборки это ~20 секунд).

## Подключение браузера

1. Откройте в браузере <http://localhost:8081/v2/languages>. Если появился длинный список языков, всё работает.
   Если страница не открывается, подождите минуту: после запуска LanguageTool загружается ~30 секунд.
2. В расширении LanguageTool откройте настройки (значок расширения → шестерёнка), в самом низу раскройте
   «Расширенные настройки» (Advanced settings) и в поле «Сервер LanguageTool» выберите
   **«Локальный сервер (localhost)»**. Если такого пункта нет, выберите «Другой сервер» и впишите `http://localhost:8081/v2`.
3. Проверьте: напишите в любом поле ввода «Я еще не знаю». Слово «еще» должно подчеркнуться с вариантом «ещё».

Тексты не уходят в интернет: расширение отправляет их только на ваш компьютер.

## Режимы: обычный текст и художественный

По умолчанию работает режим `neutral` для любых текстов: документов, статей, писем. Для художественной прозы
включите `prose`, тогда речь персонажей, имена, заикания, растяжки и слова вне нормы (`оу`, `чесслово`; в `neutral`
это замечание стиля) перестанут считаться ошибками:

1. Скопируйте `proxy/config.example.ini` в `proxy/config.ini`.
2. В строке `mode = neutral` замените `neutral` на `prose` и сохраните файл.

Перезапускать ничего не нужно, изменение действует со следующей проверки. В том же файле описано каждое правило:
их можно включать и выключать по одному. Подробности: [proxy/README.md](proxy/README.md).

## Свои слова

Имена персонажей, термины, авторские слова добавляются командой `rpdict` из папки проекта:

- Windows: `.\build\rpdict.ps1 Брумзик`
- Linux, macOS: `build/rpdict.sh Брумзик`

Скрипт спросит, как слово склоняется, и добавит все его формы. Несколько слов пишутся через пробел, удалить слово
можно с флагом `-r`, справка по всем флагам: `-h`. Через ~20 секунд слово перестаёт подчёркиваться.
Подробности: [build/README.md](build/README.md).

Свои слова хранятся в папке `words/`. Её нет в git проекта, поэтому обновление их не трогает.

### Свои слова на нескольких машинах

Сам по себе `words/` остаётся на той машине, где слова добавили. Чтобы слова были везде, храните их
в отдельном **приватном** git-репозитории (свои слова лучше не выкладывать публично):

1. Создайте пустой приватный репозиторий на GitHub или GitLab.
2. На машине, где уже есть слова: `update.sh <адрес репозитория>` (Windows: `.\update.ps1 <адрес>`).
   Он сделает `words/` git-репозиторием и отправит туда слова.
3. На каждой другой машине — та же команда. Там `words/` должен быть пуст: слова скачаются из репозитория.

Дальше хватает `update` без аргументов: он коммитит новые слова этой машины, забирает чужие и отправляет свои.
Запустите его после добавления слов и перед работой на другой машине. Если на двух машинах правили одну и ту же
строку, `git` остановится на конфликте в `words/`: исправьте файл, выполните `git -C words rebase --continue`
и снова запустите `update`.

Без этой настройки ничего не ломается: слова просто остаются на одной машине. Можно обойтись и без git:
скопируйте папку `words/` как угодно (облако, флешка), а затем запустите `rpdict` без слов.

## Обновление

- Windows: `.\update.ps1`
- Linux, macOS: `./update.sh`

Скрипт скачивает новую версию проекта, синхронизирует свои слова (если это настроено, см. выше), пересобирает
словарь и перезапускает серверы.

## N-граммы (необязательно)

N-граммы — статистика того, какие слова обычно стоят рядом. Для русского LanguageTool 6.8 использует её мало:
только чтобы различать «не» и «ни» и ещё пару похожих слов («шасси/шоссе»). Без n-грамм всё остальное работает так же,
поэтому качайте их, только если есть лишние 5 ГБ на диске.

1. Скачайте [ngram-ru-20150914.zip](https://languagetool.org/download/ngram-data/untested/ngram-ru-20150914.zip)
   (2,3 ГБ, после распаковки ~5 ГБ).
2. Распакуйте его в папку `ngrams` внутри проекта, чтобы получилось `ngrams/ru/1grams`, `ngrams/ru/2grams`, `ngrams/ru/3grams`.
   Если n-граммы уже лежат в другом месте, не переносите их: скопируйте `.env.example` в `.env` и впишите путь
   к папке, где лежит `ru`, в строку `NGRAMS_DIR=`.
3. Запустите `rpdict` без слов, чтобы перезапустить серверы.

## Если что-то не работает

- **`podman`/`docker` не найден.** Откройте новое окно терминала после установки. На Windows и macOS запустите
  Podman Desktop или Docker Desktop: без него команды не работают.
- **`compose` не найден** (`unknown command "compose"`, `looking up compose provider failed`). В Podman Desktop
  включите Compose: Settings → Resources → Compose → Setup. На Linux поставьте пакет `podman-compose`.
- **Windows: «выполнение сценариев отключено в этой системе».** Выполните шаг 5 установки для Windows.
- **Страница <http://localhost:8081/v2/languages> не открывается.** Подождите минуту после запуска. Если не
  помогло, посмотрите, что происходит: `podman compose logs` (или `docker compose logs`) в папке проекта.
  Строки `OutOfMemoryError` или `Killed` значат, что не хватает памяти: на macOS увеличьте память машины (см. установку).
- **Порт 8081 или 8082 занят** (`address already in use`). Его держит другая программа или старая копия
  проекта: `podman ps` (`docker ps`) покажет, что запущено. Остановить контейнер можно командой `podman stop имя`.
- **Расширение пишет, что сервер недоступен.** Проверьте адрес в настройках расширения (`http://localhost:8081/v2`)
  и откройте <http://localhost:8081/v2/languages> в том же браузере.
- **Проверка медленная.** Первые проверки после запуска медленнее: LanguageTool прогревается. Длинный документ он
  проверяет кусками, это тоже нормально.

Если проблема осталась, откройте issue на GitHub: опишите систему, что запускали и что вывел терминал.

## Сообщить об ошибке

Откройте issue на GitHub и выберите шаблон:

- «Предложить слова»: LanguageTool подчёркивает правильное общеупотребительное слово или известное имя (персонаж
  книги, фильма, игры). Слова можно слать пачкой, по одному на строке; пример фразы и формы необязательны.
- «Ложное срабатывание»: подчёркнут правильный текст, и дело не в словаре.
- «Ошибка не найдена»: в тексте ошибка, а подчёркивания нет.
- «Плохая подсказка»: ошибка найдена верно, а замена неправильная.

Предложенные слова добавляются в общий словарь проекта (`build/words/`) пачкой и приходят всем со следующим обновлением.
Свои имена, термины и авторские слова добавляйте себе: `rpdict слово`.

## Планы

- **Каталог словарей**: готовые наборы слов по вселенным и темам, которые можно подключить одной командой
  (если проект окажется кому-то нужен).
- **Больше пользы от n-грамм**: для русского LanguageTool сейчас использует их всего для трёх пар похожих слов.

## Как это устроено

- `build/` — словарь, свои слова (`rpdict`), исправления правил `grammar.xml`: [build/README.md](build/README.md).
- `proxy/` — фильтр на порту 8081 между расширением и LanguageTool (тот слушает порт 8082):
  [proxy/README.md](proxy/README.md).
- `compose.yaml` — LanguageTool, распаковка слов для фильтра и сам фильтр.
