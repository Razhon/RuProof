# Русский орфографический словарь (ё обязательна)

Слои, верхний главнее: Лебедев `-io` (ё обязательна) > JetBrains `ru_RU` > AOT (словарь из образа).
Е-написания слова с ё из JetBrains/AOT убираются, если их не приводит сам Лебедев (все/всё, небо/нёбо). Частоты берутся из AOT.


## Добавление слов (на каждый день)

Нужен только podman или docker (python и java запускаются во временных контейнерах). Linux: `build/rpdict.sh`, Windows: `build\rpdict.ps1`.

    rpdict [-s] [-i|-p] [-u] [-n] [-q] [-c] [-a файл] [слово...]    добавить (несколько слов — через пробел; фраза с -p — в кавычках)
    rpdict [-s] -r слово...                удалить из всех списков (размеченное слово — по лемме или одной из форм)
    rpdict [-s] -t слово...                перенести слова из другого слоя (блок tagged — целиком)
    rpdict [-s] [-i] -m [-a файл]          разметить склоняемые слова, уже лежащие в spelling.txt (с -i: в ignore.txt), по группе за раз
    rpdict -b                              полная пересборка: после обновления образа
    rpdict -h                              справка по флагам

### Два слоя слов

| Слой | Каталог | В git проекта | Флаг |
|---|---|---|---|
| свой | `words/` в корне | нет (`.gitignore`) | по умолчанию |
| общий | `build/words/` | да | `-s` |

LanguageTool принимает слова обоих слоёв. Свои слова обновление проекта не трогает, поэтому конфликтов нет.
Общий слой — словарь проекта для общеупотребительных слов, которых нет в базовом словаре; имена, термины и авторские
слова остаются в своём слое. Пополняет его автор проекта через `-s` по issue «Предложить слова»
([README.md](../README.md#сообщить-об-ошибке)): PR с правками `build/words/` не принимаются, разметку форм в диффе не
проверить. Слово, которое есть в другом слое,
повторно не добавляется. `-r` удаляет только из выбранного слоя (о втором напомнит). `-t` переносит слова в выбранный
слой: `rpdict -t Имя` — из общего в свой, `rpdict -s -t слово` — из своего в общий. Синхронизация `words/` между
машинами: [README.md](../README.md#свои-слова-на-нескольких-машинах).

`dict/` в git не хранится: `rpdict` собирает его на каждой машине (первый раз ~3 мин), `update.sh`/`update.ps1`
вызывает его после `git pull` и синхронизации `words/`.

Запуск занимает ~20 с: заново создаются файлы, которые LanguageTool читает при старте (`dict/spelling_custom.txt`,
`ignore.txt`, `added.txt`, `grammar.xml`), и пересоздаётся контейнер. `dict/ru_RU.dict` (ещё ~2 мин)
пересобирается, только когда изменились строчные слова `prohibited.txt` любого слоя (не замены, не ссылки и не слова с заглавной), `merge.py`, правило `PO` или чтение списков в `store.py`, или `build/data/`, а также при `-b`,
при смене образа и если файла нет.
`-n` — только записать файлы, без перезапуска. Без слов — собрать `dict/` и применить файлы, исправленные вручную.
`-q` — считать исправления грамматики проверенными, без `rules.py check` (так зовёт `update`, если `rules.py` здесь не правили).
`-a файл` — ответы на вопросы о склонении из файла (путь от корня репозитория, например `build/.work/answers.txt`),
по строке на вопрос, пустая строка = Enter; терминал не нужен, вопрос и ответ печатаются. Ответы кончились раньше
вопросов — выход до записи, ничего не меняется; остались лишние — выход с ошибкой (ответы ушли не в те вопросы).
Если со словами (или с `-m`) ни один файл не изменился, `rpdict` на этом заканчивает: без `rules.py` и перезапуска.
Без слов всё выполняется всегда: так применяют и правки `rules.py`.

### Как добавляется слово

Для нового слова `rpdict` показывает, как оно может склоняться, по словам словаря теггера с тем же окончанием:

    Магнусон — как склоняется?
      1) как «абдуханон» — сущ. имя м.р.
                     ед.         мн.
          И. кто?    Магнусон    Магнусоны
          Р. кого?   Магнусона   Магнусонов
          ...
      2) как «лусон» — сущ. неодуш. м.р. ...
      Enter = вариант 1 · номер = выбрать · р1 = поправить формы варианта 1 · ? = справка
      Нет подходящего? Впишите слово, которое склоняется так же, в любой форме (например: Антон)
      н = несклоняемое, спросит род · нр = наречие
      0 = принимать как есть, проверка без согласования · п = пропустить

- Выбор записывает все формы с тегами в `build/words/tagged.txt` (тогда работают орфография, согласование и предлоги:
  «нормальных статов» не ошибка). Файл можно править и вручную, по блоку на слово.
- Для слова с заглавной первыми идут имена. У второго и следующих вариантов того же слова показаны только строки,
  которые отличаются от первого (`как 1, кроме:`). Прилагательное в меню показано кратко (`какой?`, `кратк.`, `сравн.`):
  его склонение видно по именительному падежу.
- Если ни один вариант не подходит, впишите вместо номера известное слово, которое склоняется так же, в любой
  форме (`перепих` -> `смех`, `брумзалом` -> `окно`): варианты построятся по нему.
- `рN` проходит по формам варианта с вопросом падежа (`Р. ед. (кого?) [Магнусона]`, у неодушевлённых `чего?`):
  Enter оставляет форму, `-` убирает её, `a/b` даёт два варианта. Исправленная основа причастия или полной формы
  прилагательного переходит на остальные его формы (`классный` -> `класный`: `класного`, `класен`), краткой — только
  на краткие. У глагола сначала спрашиваются вид (`с/н`) и переходность (`д/н`), Enter оставляет их как у образца;
  у непереходного страдательные причастия убираются. Если у образца их нет вовсе (`дрочить`: в словаре LT 43 таких
  глагола), записываются только оба ответа вместе. Перед записью показывается полная таблица (у прилагательного
  все падежи, В. одуш. и неод.).
- Для формы причастия (`полугорящая`) есть вариант `только причастие, без глагола`: одна цепочка причастия с тегами
  `PT` (правила о причастных оборотах её видят), без личных форм глагола (`полугорю`). Если глагол употребляется,
  выбирайте его: тогда добавятся все формы, причастия тоже. `rpdict -r полугорящий` удаляет такой блок целиком.
- `нр` — наречие (`покадрово`): отдельное слово, а не краткая форма прилагательного.
- В `rpdict -m` меню группы не показывает вариантов, которые теряют одно из её слов (`клёво клёвый`: «как царёв»
  без `клёвый`; `стебанутый стебануть`: «только причастие» без `стебануть`). Слова, перечисленные в `rpdict` через
  пробел, спрашиваются по одному.
- Если среди слов есть краткая форма ср.р. на -о (`клёво`), после выбора прилагательного `rpdict` спросит
  `клёво — ещё и наречие?` (Enter = да): наречие ложится отдельным блоком с тегом `ADV`, как `быстро` у LT.
  В файле ответов `-a` это ещё одна строка. `rpdict -r клёво` удалит и наречие, и краткую форму из блока `клёвый`.
- У одного написания бывает несколько значений: `Тесла` (он) и `Тесла` (машина), `Шевчук` м.р. и ж.р. Допишите `+`
  к любому ответу (`1+`, `р2+`, `Антон+`, `н+`, `нр+`): вариант запишется, и меню откроется снова для того же слова
  (Enter, `0` или `п` там — готово). Значения ложатся в один блок `tagged.txt`: заголовки подряд, формы вместе.
  Без своего рода в словаре LT ловит согласование (`Новая Маккенна сказала`, если Маккенна записан только м.р.).
- Общий род (`сирота`, `визави`: «бедный сирота» и «бедная сирота»): если образец такого рода (впишите `сирота`),
  в меню будет один вариант «общ. р. (м. и ж.)» вместо двух; иначе ответьте `мж` на вопрос о роде (после `н` или
  `рN`). Слово записывается сразу как м.р. и ж.р., с мн. ч.
- Слово уже есть в словаре или в личном списке: `rpdict` показывает его значения и спрашивает
  `Enter = ничего · д = поправить это склонение · з = ещё значение`. `д` у слова базового словаря только дописывает
  формы и теги (убрать нельзя), у своего слова правит одно значение на месте. `з` открывает обычное меню, результат
  дописывается к блоку слова. Убрать одно значение нельзя: `rpdict -r слово` удаляет все, затем добавьте нужные заново.
- Проверяйте причастие в строке глагола: у теггера есть и е, и ё (заигноренный / заигнорённый), а верное зависит
  от ударения, поэтому варианты различаются именно здесь.
- `0` — только орфография (`spelling.txt`): частицы, междометия, пары слов (`его-то`, `месяц-два`, `нафиг`).
- Недостающая форма известного слова (`задействуя`) предлагается как таковая: одна размеченная строка, без догадок.
- Предупреждение появляется, если в словаре есть слово с ё (`признаешься` -> `признаёшься`) или слово уже известно.
- Имена — с заглавной буквы; несклоняемое имя получает 6 падежей (`Брум` = `н`, `ж`).
- Вопросы о склонении задаются только в терминале. Если ввод перенаправлен (`echo | rpdict …`), слово уходит в
  `spelling.txt`, и `rpdict` об этом предупреждает.

### Какой файл выбрать

| Файл | Флаг | Слово принимается | Предлагается как исправление | Что сюда класть |
|---|---|---|---|---|
| `tagged.txt` | (нет, выбор 1–3/н/нр) | да, все формы | да | склоняемые слова: имена, сленг, жаргон, составные (`гримуар`, `скилл`, `Лавкрафт`) |
| `spelling.txt` | (нет, выбор 0) | да | да | слова, которые не склоняются или не поддаются разметке |
| `tagged.txt`, метка `(ignore)` | `-i`, выбор 1–3/н/нр | да, все формы | нет | мат и грубый сленг, который склоняется (`мудак`, `ебать`) |
| `ignore.txt` | `-i`, выбор 0 | да | нет | междометия, растянутые звуки, сокращения, намеренные искажения (`ха-ха-ха`, `э-э-э`, `досл`) |
| `prohibited.txt` | `-p` | **нет** (удаляется) | нет; предлагается замена из файла | неверная форма, которая есть в словаре и должна отмечаться (в любом регистре); слово с заглавной — только заглавная в середине предложения; ошибка с точной заменой вместо догадки орфографии; неверная фраза (`во внутрь`) |

У каждого файла слов в начале есть шапка из строк `#`: что в нём лежит и когда класть слово сюда. `rpdict` пишет
её в файл, где нет ни одной строки `#`, а свою шапку, написанную руками, сохраняет. У `tagged.txt` шапка —
первый абзац из одних комментариев, отделённый от блоков пустой строкой.

- `-i` задаёт те же вопросы о склонении. Размеченное слово ложится в `tagged.txt`, и в конце его заголовка ставится
  метка `(ignore)` (`# мудак: как «чудак» — сущ. одуш. м.р. (ignore)`). Его формы попадают в `dict/ignore.txt`, а теги —
  в `added.txt`, как у обычного слова. Согласование и подсказки падежа (`к мудаком` → `к мудаку`) работают, но
  как исправление опечатки слово не предлагается. Если у блока есть хоть одно значение без метки, предлагаются все
  его формы. Сменить вид блока можно так: `rpdict -r слово`, затем добавить его заново. `rpdict -s -i -m` размечает
  слова, уже лежащие в `ignore.txt`.
- `-u` помечает слово как слово вне литературной нормы: разговорное, просторечное, новое, жаргонное (`оу`, `чесслово`,
  `кхм`, `чувак`). Слово добавляется как обычно (с `-i` или без), затем `rpdict` спрашивает замену для нейтрального
  текста (`чесслово` → `честное слово`, Enter — без замены) и ссылку-подтверждение, затем пишет строку `слово`,
  `слово = замена` или `слово = замена https://…` в `nonstandard.txt` слоя. В режиме `neutral` LanguageTool отмечает такое слово замечанием стиля `RU_NONSTANDARD` с
  заменой, в `prose` замечания нет. Так же прокси обходится с просторечием из списка самого LT (`чё`, `щас`, правило
  `RU_SIMPLE_REPLACE`). Повтор `-u` для помеченного слова меняет замену (`-` — убрать). Снять пометку,
  оставив слово, — удалить строку из `nonstandard.txt` и запустить `rpdict`; `-r` убирает слово вместе с пометкой.
  Тегов слова пометка не меняет (почему — в `build/py/rules.py`, `nonstandard`), поэтому согласование, падежи и
  подсказки к опечаткам работают как раньше. Предлагать ли слово как исправление, решает, как обычно, `-i`: короткие
  (`ик`, `кхм`) лучше с `-i`, иначе они полезут в подсказки к чужим опечаткам.
- `-p` спрашивает замену (`нахер` → `на хер`, Enter — без замены) и ссылку-подтверждение (`https://…`, Enter — без
  ссылки) и пишет строку `слово`, `слово = замена` или `слово = замена https://…` в `prohibited.txt` слоя. Слово без
  замены отмечает орфография со своими подсказками. Слово с заменой отмечает правило `RU_PROHIBITED` с подсказкой из
  файла и ссылкой в «Подробнее»: орфография не находит дефисную или раздельную замену (`мда` → `м-да`). Слово с заглавной
  (`Лавкрафтовский`) из словаря не удаляется: правило отмечает его только в середине предложения (не в начале, не после
  тире, кавычки, скобки, двоеточия) и подсказывает строчное. Без метки — только эта форма; с меткой `*`
  (`rpdict -p 'Лавкрафтовский*'`, в sh — в кавычках) — все формы слова, замену `-p` тогда не спрашивает. Повтор `-p` для записанного слова меняет замену и ссылку (Enter —
  оставить, `-` — убрать), словарь при этом не пересобирается. Ссылку понимает и `nonstandard.txt`.
  Фраза (`rpdict -p 'во внутрь'`, в кавычках) записывается только с заменой: её слова верны по отдельности, и
  отметить её может лишь правило `RU_PROHIBITED`. Словарь она не пересобирает, регистр не важен, форма — ровно записанная.
- Слово, которое уже есть в базовом словаре, при добавлении пропускается; `rpdict -c` убирает такие остатки.
- Слова с неразрывным дефисом U+2011 LanguageTool не проверяет вовсе; `rpdict -m` заменяет его на `-`.
- Образ закреплён (`6.8` в `compose.yaml`, `rpdict` читает версию оттуда): файлы в `dict/` собраны из него.
  Для новой версии поменяйте там тег и запустите `rpdict`: смену образа он замечает сам и делает то же, что `-b`:
  свежие дампы словарей, индекс парадигм (~2 мин один раз), исправления грамматики. Сборка останавливается, если исправление больше не совпадает со своим правилом.

### Исправления грамматики

`build/py/rules.py` правит ложные срабатывания `grammar.xml` из образа (у каждой правки указано точное число совпадений).
После каждого изменения исправлений и при `-b` запускается `rules.py check`: он прогоняет все примеры изменённых правил
и случаи рядом с каждой правкой на перезапущенном сервере и падает, если ошибка потерялась или появилось новое ложное
срабатывание. `update.sh`/`update.ps1` зовут `rpdict -q`, если `rules.py` в рабочей копии не изменён: он не проверяет, а сразу записывает исправления как проверенные (примеры
прогнал автор, а у пользователя проверка только тратит время и процессор, в том числе при следующем добавлении слова). Новое исправление: сначала проверьте его на всех 2453 примерах файла и на своих текстах, потом добавьте в `PATCHES`.

Так же правится `replace.txt` из образа — список правила `RU_SIMPLE_REPLACE` («чё — просторечие, исправление: что»).
LT пишет «просторечие» у каждой записи без пометки, а прокси в `prose` такие замечания снимает. Поэтому `REPLACE_DROP`
убирает из списка записи, которые не просторечие: ошибки и обычные слова (`креативный`, `шаверма`). Правило одно:
`replace.txt` мы только чистим, а точные замены наших ошибок (слова и фразы) живут в `prohibited.txt`. Убранную ошибку
отмечает орфография; если её нет ни в словаре, ни у орфографии (`придти`, `во внутрь`) или первый вариант орфографии
неверен (`оплоченный` → `сплочённый`), она записана в `prohibited.txt` с заменой из `replace.txt`. Каждая запись
`REPLACE_DROP` должна найтись в образе ровно раз, иначе сборка останавливается.

Обязательный случай может быть кортежем `(текст, вариант, …)`: ровно столько замечаний, с этими первыми вариантами
исправления по порядку (`None` — без варианта). `type` правила (например, `style`) проверяется как `issueType` у каждого замечания.
Для работы над правкой (запуск в контейнере; одна команда для PowerShell и sh, сервер поднят `rpdict` или `podman compose up -d`):

```
podman run --rm --network container:$(podman compose ps -q languagetool) -v "${PWD}:/p" -w /p docker.io/library/python:3.15-slim python3 build/py/rules.py …
```

- `diff [id…]`: что правки меняют в правилах образа (сервер не нужен: запускайте без `--network …`).
- `try http://localhost:8010 ФАЙЛ [id…]`: замечания LT на фразы из файла (UTF-8, фразы через пустую строку); с id — только
  эти правила, включая выключенные. Текст берётся из файла: кириллица в аргументах командной строки Windows портится.
- `check http://localhost:8010 [id…]`: проверка только этих правил. Изменили одни случаи рядом с правкой — перезапуск не нужен,
  хватит её; изменили саму правку — `rpdict` (он применит её, перезапустит LT и сделает полный `check`).

Если после обновления образа правка не совпала, `apply` перечисляет все такие правки со строкой правила в
`build/.work/grammar.orig.xml`; сломанный XML в `ADD` останавливает сборку до перезапуска LT.

N-граммы необязательны: каталог `ru/` в `ngrams/` или в `NGRAMS_DIR` из `.env` ([README.md](../README.md#n-граммы-необязательно)).

## Источники (нужны только для пересоздания `build/data/*.txt.gz`)

1. Лебедев: `hunspell-ru-lebedev-io-*.rpm` из ALT Linux p10 (`ftp.altlinux.org/.../p10/branch/noarch/RPMS.classic/`), распаковать `usr/share/myspell/ru_RU-lebedev-io.{dic,aff}`. JetBrains: `ru_RU.dic`/`ru_RU.aff` из `github.com/JetBrains/hunspell-dictionaries/ru_RU`.
2. Развернуть через `unmunch` (контейнер Debian, пакет `hunspell-tools`): `unmunch X.dic X.aff | sort -u | gzip -9 > io.txt.gz` / `jb.txt.gz` (UTF-8).
3. AOT не хранится: `build.sh prep` выгружает его из образа (koi8-r), `merge.py` читает его напрямую.

Просмотрите `build/.work/report-dropped-e-forms.txt` (убранные е-варианты) и `report-added-from-jb-aot.txt`.
